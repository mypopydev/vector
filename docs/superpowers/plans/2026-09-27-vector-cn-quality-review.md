# 《向量》中文译本 · 准确性与精炼度复核计划

**目标**：确认译文**准确**（无漏译、误译、增译、数字/专名错）且**精炼**（无翻译腔、无冗余、跨章风格统一），把查实的问题修掉，并重新产出 PDF 与网页版。

## 一、侦察结论（决定了方案怎么设计）

### 已经机械验证过的，不必重复
| 校验 | 结果 |
|---|---|
| `check_structure.py`（段/图/公式/尾注/节标题/分页 中英 1:1） | 严重 0 |
| `check_math.py`（公式逐条一致且可编译） | 严重 0 |
| `check_terms.py`（术语、禁用译名） | 严重 0 |
| `check_baseline.py`（PDF 缺字形/丢字/越界） | 严重 0 |

**所以复核必须瞄准机器查不了的东西：语义是否忠实、文字是否精炼。**

### 关键发现

1. **段落级 1:1 对齐是可靠的**（结构校验已证明），可以拿来做逐段双语对照复核 —— 这是整个方案的基础。

2. **长度比率是弱信号，不能当缺陷判据。**
   各章「汉字/英文词」在 **1.65–2.03** 之间（中位约 1.78）。抽查比率最高的一章（2.17）：
   译文忠实、没有加料，多出的篇幅来自「中文名（Latin Name）」这种体例要求和汉语虚词。
   → 比率只能用来**发现风格不统一**（跨章 0.38 的落差说明不同译者的行文密度有差异），不能直接判「啰嗦」。

3. **数字保全已验证**：逐段比对后，**没有任何一段丢掉数字**（英文段有数字而中文段既无阿拉伯数字也无汉字数字的情况 = 0 处）。这是一项很强的信号。

4. **精确数值核对需要专门处理汉字数字**，我原型试了两版：
   - 不做汉字数字归一化 → 91 处候选，全是「三千七百年」这类假阳性
   - 归一化过激（把「一个」「两种」也算数字）→ 910 处噪声，**比不做还糟**
   - 收紧到只认「含十百千万亿」或「数字+年/页」的数量短语 → 落到 5 处高信号候选，抽查 1 处确认是假阳性（我的正则漏了「分之」结构，是脚本的 bug，不是译文的问题）
   → 结论：这个检查**值得做但必须写对**，且产出量低，属于「守卫」而非「主力」

5. **译名一致性可以机械提取**：扫描「中文（Latin Name）」配对共 **554 种**外文名，其中译名不唯一的有 **88 种**。但含大量前缀噪声（「父亲阿奇博尔德」「导师阿尔弗雷德·克莱布施」都是同一个人），需要一个角色词修剪表。
   → 这是一个高价值、可自动化的候选清单。

**结论：机械手段只能做守卫，真正的主力是逐段双语精读。**

## 二、三层方法

### 第 1 层：机械守卫 —— 新增 `tools/check_fidelity.py`

| 检查 | 判据 | 严重度 |
|---|---|---|
| 数字保全 | 逐段比数字（含汉字数字归一化）；英文段有数字而中文段完全没有 → | 严重 |
| 精确数值 | 归一化后比对多重集，英文侧 3 位以上数字/小数在中文侧缺失 → | 中等 |
| 专名保全 | 逐段比拉丁字母 token（人名/书名/机构）；英文段有、中文段没有 → | 中等 |
| 引文保全 | 英文成对引号内的内容在中文段里找不到对应引号片段，统计缺失率 → | 中等 |
| 译名一致 | `中文（Latin）` 配对 + 角色词修剪（父亲/导师/学生/传记作者/爵士…）→ 同一外文名多种中文译法 | 中等 |
| 长度异常 | 段落级比率 top/bottom 5%（**仅提示，不自动改**） | 轻微 |

输出 `review/fidelity.md`，所有条目带 `文件:行号`。

### 第 2 层：逐章双语精读（并行子代理，一章一个）

每个审读员拿到：`en/<章>.md`、`cn-book/<章>.md`、`docs/术语表.md`、`docs/译名表-人名.md`、`docs/翻译风格指南.md`、findings 模板。

**逐段对照，只报可定位、可验证的问题**，格式：

```
- cn 行号 | 严重度 | 类型 | 原文片段 | 现译片段 | 建议改法
```

- **类型**：漏译 / 增译 / 误译 / 术语 / 专名 / 数字 / 指代不清 / 翻译腔 / 冗余
- **严重度**：
  - `严重` = 意思错了、信息漏了、数字或专名错
  - `中等` = 意思对但读着别扭、术语不统一、指代不明
  - `轻微` = 可更精炼，不改也不影响理解

**硬约束（防止「精炼」变成「改坏」）**：
- 不得删掉原文的限定语（maybe / seemingly / arguably 这类分寸词）
- 不得为了顺口改写事实、数字、专名
- 不得整段重写；建议要具体到「删哪几个字 / 换哪个词」
- 作者的口语化语气、插入语、破折号补充是风格，不算冗余

### 第 3 层：跨章风格统一

- 统计各章中位比率、平均句长、常见句式（「的」字密度、被动句、「进行…的处理」这类名词化表达）
- 找出偏离中位数 2σ 的章节，做定向修订
- 统一：专名首现格式、人称与时态习惯、引号与标点、数字写法（阿拉伯数字 vs 汉字数字的取舍）

## 三、修订与验收

**最小改动原则**：逐条 apply，每条记录「改前 → 改后」。

改完必须全绿再交付：

```bash
python3 tools/check_structure.py      # 0 严重
python3 tools/check_math.py           # 0 严重
python3 tools/check_terms.py          # 0 严重
python3 tools/check_fidelity.py       # 0 严重
python3 tools/build_pdf.py && python3 tools/check_baseline.py   # 0 严重
python3 tools/build_site.py --check && (站点仓库) mkdocs build --strict
```

最后出 `review/quality-report.md`：改动条数、类型分布、剩余「轻微」清单（说明为何不改）。

## 校准过程中踩掉的四个坑（都写进脚本注释了）

| 坑 | 表现 | 正确做法 |
|---|---|---|
| 汉字数字归一化过宽 | 把「一个」「两种」当数字 → **910 处噪声**，比不做还糟 | 只认含「十百千万亿」或后接计量单位的数量短语 |
| 严重判据过狠 | 英文 2-D/3-D 对中文「二维/三维」→ 21 处假「严重」 | 只对 3 位以上数值与小数判严重 |
| 剪词修剪专名 | `trim_name` 把「**向**量委员会」剪成「量委员会」 | 改表驱动后缀匹配，前缀定语天然容忍，不剪词 |
| 引文阈值同尺度 | 英文 10 字符 ≈ 中文 4 字，同阈值必然误报 | 英文 ≥10 字符、中文 ≥4 字 |

## 已确认的事实（不需要再查）

1. **没有任何段落整段丢掉数字**（英文段有数字、中文段完全没有 = 0 处）
2. **译名表里的外文名都能在译稿中找到对应写法**；`中文（Latin）` 配对与表中译名**无实质冲突**（此前的「麦克斯韦派 / 麦克斯韦学派」类候选经表驱动复核后已清零）
3. 年代写法差异（英文 `1880s` ↔ 中文「19 世纪 80 年代」）是等价表达，已降级

## 结论

机械手段的天花板已经摸到：**守卫只能证明「没丢东西」，证明不了「译得对、写得精」**。
真正的产出必须来自批次的逐段双语精读。
